# Django

Django is a high-level Python web framework that encourages rapid development and clean, pragmatic design. Built by experienced developers, it takes care of much of the hassle of web development, enabling you to focus on writing your app without needing to reinvent the wheel. Django follows the Model-View-Template (MVT) architectural pattern and includes an object-relational mapper (ORM), URL routing, template engine, form handling, authentication system, and admin interface out of the box.

Django emphasizes reusability and "pluggability" of components, the principle of don't repeat yourself (DRY), and convention over configuration. It provides a robust set of tools for building secure, scalable web applications, from simple content sites to complex database-driven applications. The framework supports both synchronous and asynchronous programming patterns, includes built-in protection against common security threats, and offers comprehensive documentation and a vibrant community ecosystem.

## Models and Database ORM

Django's ORM maps Python classes to database tables. Each model class represents a database table, and each attribute represents a database field. The ORM supports all common database relationships and provides a rich query API.

```python
# polls/models.py
from django.db import models
from django.utils import timezone
import datetime


class Question(models.Model):
    question_text = models.CharField(max_length=200)
    pub_date = models.DateTimeField("date published")

    def __str__(self):
        return self.question_text

    def was_published_recently(self):
        return self.pub_date >= timezone.now() - datetime.timedelta(days=1)


class Choice(models.Model):
    question = models.ForeignKey(Question, on_delete=models.CASCADE)
    choice_text = models.CharField(max_length=200)
    votes = models.IntegerField(default=0)

    def __str__(self):
        return self.choice_text


# Blog models with various relationships
class Blog(models.Model):
    name = models.CharField(max_length=100)
    tagline = models.TextField()

    def __str__(self):
        return self.name


class Author(models.Model):
    name = models.CharField(max_length=200)
    email = models.EmailField()

    def __str__(self):
        return self.name


class Entry(models.Model):
    blog = models.ForeignKey(Blog, on_delete=models.CASCADE)
    headline = models.CharField(max_length=255)
    body_text = models.TextField()
    pub_date = models.DateField()
    mod_date = models.DateField(default=datetime.date.today)
    authors = models.ManyToManyField(Author)
    number_of_comments = models.IntegerField(default=0)
    rating = models.IntegerField(default=5)

    def __str__(self):
        return self.headline
```

## QuerySet API

Django provides a powerful database abstraction API for creating, retrieving, updating, and deleting objects. QuerySets are lazy and chainable.

```python
# Using Django's interactive shell
# python manage.py shell

from django.utils import timezone
from polls.models import Question, Choice

# Create objects
q = Question(question_text="What's new?", pub_date=timezone.now())
q.save()

# Access fields
print(q.id)           # 1
print(q.question_text)  # "What's new?"
print(q.pub_date)     # datetime.datetime(...)

# Update objects
q.question_text = "What's up?"
q.save()

# Retrieve all objects
Question.objects.all()  # <QuerySet [<Question: What's up?>]>

# Filter with keyword arguments
Question.objects.filter(id=1)
Question.objects.filter(question_text__startswith="What")

# Get single object
current_year = timezone.now().year
Question.objects.get(pub_date__year=current_year)

# Primary key lookup shortcut
Question.objects.get(pk=1)

# Related object access through ForeignKey
q = Question.objects.get(pk=1)
q.choice_set.all()  # <QuerySet []>

# Create related objects
q.choice_set.create(choice_text="Not much", votes=0)
q.choice_set.create(choice_text="The sky", votes=0)
c = q.choice_set.create(choice_text="Just hacking again", votes=0)

# Reverse relationship access
c.question  # <Question: What's up?>

# Count related objects
q.choice_set.count()  # 3

# Filter across relationships with double underscores
Choice.objects.filter(question__pub_date__year=current_year)

# Delete objects
c = q.choice_set.filter(choice_text__startswith="Just hacking")
c.delete()

# Bulk operations
Blog.objects.create(name="Beatles Blog", tagline="All the latest Beatles news.")
Entry.objects.filter(pub_date__year=2024).update(rating=5)
```

## Views and URL Routing

Views are Python functions or classes that receive web requests and return web responses. URL routing maps URL patterns to views using the URLconf.

```python
# polls/views.py
from django.http import HttpResponse, Http404
from django.shortcuts import render, get_object_or_404
from .models import Question


# Function-based view
def index(request):
    latest_questions = Question.objects.order_by("-pub_date")[:5]
    context = {"latest_questions": latest_questions}
    return render(request, "polls/index.html", context)


def detail(request, question_id):
    question = get_object_or_404(Question, pk=question_id)
    return render(request, "polls/detail.html", {"question": question})


def vote(request, question_id):
    question = get_object_or_404(Question, pk=question_id)
    try:
        selected_choice = question.choice_set.get(pk=request.POST["choice"])
    except (KeyError, Choice.DoesNotExist):
        return render(request, "polls/detail.html", {
            "question": question,
            "error_message": "You didn't select a choice.",
        })
    else:
        selected_choice.votes += 1
        selected_choice.save()
        return redirect("polls:results", question_id=question.id)


# polls/urls.py
from django.urls import path
from . import views

app_name = "polls"
urlpatterns = [
    path("", views.index, name="index"),
    path("<int:question_id>/", views.detail, name="detail"),
    path("<int:question_id>/vote/", views.vote, name="vote"),
]


# mysite/urls.py (root URLconf)
from django.contrib import admin
from django.urls import include, path

urlpatterns = [
    path("polls/", include("polls.urls")),
    path("admin/", admin.site.urls),
]
```

## Class-Based Views

Class-based views provide an alternative way to implement views as Python objects, enabling code reuse through inheritance and mixins.

```python
# views.py
from django.http import HttpResponse
from django.views import View
from django.views.generic import ListView, DetailView, CreateView
from .models import Question


# Basic class-based view
class MyView(View):
    def get(self, request):
        return HttpResponse("Hello, World!")

    def post(self, request):
        return HttpResponse("Posted!")


# Generic list view
class QuestionListView(ListView):
    model = Question
    template_name = "polls/index.html"
    context_object_name = "latest_questions"
    queryset = Question.objects.order_by("-pub_date")[:5]


# Generic detail view
class QuestionDetailView(DetailView):
    model = Question
    template_name = "polls/detail.html"


# Customizing class attributes
class GreetingView(View):
    greeting = "Good Day"

    def get(self, request):
        return HttpResponse(self.greeting)


class MorningGreetingView(GreetingView):
    greeting = "Morning to ya"


# urls.py
from django.urls import path
from .views import MyView, QuestionListView, QuestionDetailView, GreetingView

urlpatterns = [
    path("about/", MyView.as_view(), name="about"),
    path("questions/", QuestionListView.as_view(), name="question-list"),
    path("questions/<int:pk>/", QuestionDetailView.as_view(), name="question-detail"),
    path("greet/", GreetingView.as_view(greeting="G'day"), name="greet"),
]
```

## Shortcut Functions

Django provides convenience functions in django.shortcuts for common view patterns, reducing boilerplate code.

```python
from django.shortcuts import render, redirect, get_object_or_404, get_list_or_404
from django.http import Http404
from .models import Question, Choice


# render() - Renders template with context and returns HttpResponse
def question_list(request):
    questions = Question.objects.all()
    return render(request, "polls/list.html", {"questions": questions})


# get_object_or_404() - Gets object or raises Http404
def question_detail(request, pk):
    question = get_object_or_404(Question, pk=pk)
    return render(request, "polls/detail.html", {"question": question})


# Can also use with QuerySet
def choice_detail(request, pk):
    choice = get_object_or_404(
        Choice.objects.select_related("question"),
        pk=pk
    )
    return render(request, "polls/choice.html", {"choice": choice})


# get_list_or_404() - Gets list or raises Http404 if empty
def recent_questions(request):
    questions = get_list_or_404(Question, pub_date__year=2024)
    return render(request, "polls/recent.html", {"questions": questions})


# redirect() - Returns redirect response
def vote_success(request, question_id):
    # Redirect to URL name with arguments
    return redirect("polls:results", question_id=question_id)


# Redirect to absolute URL
def external_redirect(request):
    return redirect("/some/url/")


# Redirect to model with get_absolute_url()
def redirect_to_question(request, pk):
    question = get_object_or_404(Question, pk=pk)
    return redirect(question)  # Calls question.get_absolute_url()

# Async versions available
```

## Forms

Django's form system handles HTML form rendering, data validation, and cleaning. Forms can be defined manually or generated from models.

```python
# forms.py
from django import forms
from .models import Question


# Manual form definition
class ContactForm(forms.Form):
    name = forms.CharField(max_length=100)
    email = forms.EmailField()
    message = forms.CharField(widget=forms.Textarea)
    send_copy = forms.BooleanField(required=False)

    def clean_email(self):
        email = self.cleaned_data["email"]
        if "spam" in email:
            raise forms.ValidationError("Invalid email address")
        return email


# ModelForm - Form generated from model
class QuestionForm(forms.ModelForm):
    class Meta:
        model = Question
        fields = ["question_text", "pub_date"]
        widgets = {
            "pub_date": forms.DateTimeInput(attrs={"type": "datetime-local"}),
        }


# views.py
from django.shortcuts import render, redirect
from .forms import ContactForm, QuestionForm


def contact_view(request):
    if request.method == "POST":
        form = ContactForm(request.POST)
        if form.is_valid():
            # Process the data
            name = form.cleaned_data["name"]
            email = form.cleaned_data["email"]
            message = form.cleaned_data["message"]
            # Send email, save to database, etc.
            return redirect("success")
    else:
        form = ContactForm()

    return render(request, "contact.html", {"form": form})


def create_question(request):
    if request.method == "POST":
        form = QuestionForm(request.POST)
        if form.is_valid():
            question = form.save()
            return redirect("polls:detail", question_id=question.id)
    else:
        form = QuestionForm()

    return render(request, "polls/create.html", {"form": form})
```

```python
from django.contrib.auth import authenticate, login, logout

def login_view(request):
    if request.method == "POST":
        username = request.POST["username"]
        password = request.POST["password"]
```

## Background Tasks (Django 6.0+)

Django's Tasks framework enables running code outside the HTTP request-response cycle for background processing like sending emails or data processing.

```python
# settings.py
TASKS = {
    "default": {
        "BACKEND": "django.tasks.backends.immediate.ImmediateBackend"
    }
}


# tasks.py
from django.core.mail import send_mail
from django.tasks import task


@task
def email_users(emails, subject, message):
    """Send email to multiple users in background."""
    return send_mail(
        subject=subject,
        message=message,
        from_email=None,
        recipient_list=emails
    )


@task
def process_data(data_id):
    """Process data asynchronously."""
    from .models import DataItem
    item = DataItem.objects.get(pk=data_id)
    # Perform expensive computation
    item.processed = True
    item.save()
    return {"status": "completed", "id": data_id}


# views.py - Enqueue tasks
from .tasks import email_users, process_data

def send_notification(request):
    # Enqueue task for background execution
    result = email_users.enqueue(
        emails=["user@example.com"],
        subject="Welcome!",
        message="Thanks for signing up."
    )
    return HttpResponse(f"Task queued: {result.id}")


def start_processing(request, pk):
    result = process_data.enqueue(data_id=pk)
    return JsonResponse({"task_id": str(result.id)})


# Checking task results
from django.tasks import default_task_backend

def check_task(request, task_id):
    result = default_task_backend.get_result(task_id)
    return JsonResponse({
        "status": result.status,
        "result": result.result if result.is_finished else None
    })
```

```python
# Custom management command
# polls/management/commands/close_old_polls.py

from django.core.management.base import BaseCommand
from django.utils import timezone
from polls.models import Question


class Command(BaseCommand):
    help = "Closes polls that have been open for more than 30 days"

    def add_arguments(self, parser):
        parser.add_argument(
            "--days",
            type=int,
            default=30,
            help="Number of days after which polls are closed",
        )
        parser.add_argument(
            "--dry-run",
            action="store_true",
            help="Show what would be done without making changes",
        )

    def handle(self, *args, **options):
        days = options["days"]
        cutoff = timezone.now() - timezone.timedelta(days=days)

        old_questions = Question.objects.filter(
            pub_date__lt=cutoff,
            is_active=True
        )

        if options["dry_run"]:
            self.stdout.write(f"Would close {old_questions.count()} polls")
            return

        count = old_questions.update(is_active=False)
        self.stdout.write(
            self.style.SUCCESS(f"Successfully closed {count} polls")
        )


# Usage:
# python manage.py close_old_polls --days=60
# python manage.py close_old_polls --dry-run
```

## Summary

Django excels at building content management systems, e-commerce platforms, social networks, APIs, and any database-driven web application. Its "batteries included" philosophy means you get authentication, admin interfaces, ORM, form handling, and security features without additional dependencies. The framework is particularly well-suited for rapid prototyping while remaining robust enough for high-traffic production sites, used by companies like Instagram, Mozilla, and Pinterest.

Integration patterns typically involve defining models first, creating migrations, building views and URL routes, and using templates for HTML rendering or Django REST Framework for APIs. Django follows a request-response cycle where middleware processes requests, URL routing dispatches to views, views interact with models and forms, and templates render responses. The framework integrates seamlessly with PostgreSQL, MySQL, SQLite databases, Redis for caching, and various task queues for background processing through the new Tasks framework in Django 6.0.
