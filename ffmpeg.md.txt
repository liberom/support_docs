## OpenCL Video Filters

To enable compilation of these filters you need to configure FFmpeg with `--enable-opencl`.
Running OpenCL filters requires you to initialize a hardware device and to pass that device to all filters in any filter graph.

### Initialization Commands

* **-init_hw_device opencl[=name][:device[,key=value...]]**
  Initialise a new hardware device of type opencl called name, using the given device parameters.

* **-filter_hw_device name**
  Pass the hardware device called name to all filters in any filter graph.

For more detailed information see https://www.ffmpeg.org/ffmpeg.html#Advanced-Video-options

### Example

```

**Note:** Since OpenCL filters are not able to access frame data in normal memory, all frame data needs to be uploaded (`hwupload`) to hardware surfaces connected to the appropriate device before being used and then downloaded (`hwdownload`) back to normal memory. Note that `hwupload` will upload to a surface with the same layout as the software frame, so it may be necessary to add a `format` filter immediately before to get the input into the right format and `hwdownload` does not support all formats on the output - it may be necessary to insert an additional `format` filter immediately following in the graph to get the output in a supported format.
```

```APIDOC
## Initialize Vulkan Hardware Device

### Description
Initializes a new hardware device of type Vulkan. This device can then be passed to other Vulkan filters.

### Method
This is typically used as an FFmpeg option, not a direct API endpoint.

### Endpoint
N/A

### Parameters
#### Command-line Options
- **-init_hw_device** (string) - Required - Specifies the hardware device type and its parameters.
  - `vulkan[=name][:device[,key=value...]]`
    - `name`: Alias for the Vulkan device.
    - `device`: Specifies the physical Vulkan device to use (e.g., `0` for the first device).
    - `key=value`: Additional options for the Vulkan device. Supported options include:
      - `debug` (integer) - Switches validation layers on if set to 1.
      - `linear_images` (boolean) - Allocates linear images. Does not apply to decoding.
      - `disable_multiplane` (boolean) - Disables multiplane images. Does not apply to decoding.
      - `avoid_host_import` (boolean) - Avoids the use of dynamic host memory imports.

#### Filter Graph Option
- **-filter_hw_device** (string) - Required - Passes the initialized hardware device to all filters in a filter graph.
  - `name`: The alias of the Vulkan device initialized with `-init_hw_device`.

### Response

#### Success Response (N/A)

#### Response Example

### FFmpeg Interval Command Syntax

Source: https://ffmpeg.org/documentation.html/ffmpeg-all

Defines the basic syntax for specifying time intervals and associated commands in FFmpeg. An interval is defined by a start and optional end time, followed by a list of commands to be executed when the current frame time enters or leaves this interval. Whitespace and comments starting with '#' are ignored.

```bnf
START[-END] COMMANDS;
COMMANDS ::= COMMAND [,COMMANDS]
COMMAND       ::= ["[" COMMAND_FLAGS "]"] TARGET COMMAND [ARG]
COMMAND_FLAGS ::= COMMAND_FLAG [("|"|"+")COMMAND_FLAG]
COMMAND_FLAG  ::= "enter" | "leave"
INTERVAL      ::= START[-END] COMMANDS
INTERVALS     ::= INTERVAL[;INTERVALS]
```

### life Filter Documentation

Source: https://ffmpeg.org/documentation.html/ffmpeg-all

This section details the 'life' filter, its purpose, available options, and provides usage examples.

```APIDOC
## life

### Description
Generate a life pattern based on a generalization of John Conway’s life game. The source represents a life grid where each pixel is a cell that can be alive or dead. Cells interact with their eight neighbors, and the grid evolves based on a specified rule.

### Method
`life` (filter)

### Endpoint
N/A (This is an FFmpeg filter, not a web API endpoint)

### Parameters
#### Options
- **f, filename** (string) - Optional - Set the file from which to read the initial grid state. Non-whitespace characters are alive cells; newlines delimit rows. If not specified, the initial grid is generated randomly.
- **r, rate** (integer) - Optional - Set the video rate (frames per second). Defaults to 25.
- **ratio, random_fill_ratio** (float) - Optional - Set the random fill ratio for the initial random grid (0 to 1). Defaults to 1/PHI. Ignored when a file is specified.
- **seed, random_seed** (integer) - Optional - Set the seed for filling the initial random grid (0 to UINT32_MAX). If not specified or -1, a good random seed is attempted.
- **rule** (string or integer) - Optional - Set the life rule. Can be specified as "SNS/BNB" (e.g., "S23/B3") or an 18-bit integer encoding. Defaults to "S23/B3" (Conway's original rule).
- **s, size** (string) - Optional - Set the size of the output video (e.g., "320x240"). If filename is specified, defaults to input file size and centers the input grid. If no filename, defaults to "320x240".
- **stitch** (integer) - Optional - If set to 1, stitch the left/right and top/bottom grid edges together. Defaults to 1.
- **mold** (integer) - Optional - Set cell mold speed (0-255). A dead cell transitions from `death_color` to `mold_color` with this step.
- **life_color** (color) - Optional - Set the color of living or newly born cells.
- **death_color** (color) - Optional - Set the color of dead cells. If mold is set, this is the initial color.
- **mold_color** (color) - Optional - Set the mold color for definitely dead and moldy cells.

*Note: For color options, refer to the "Color" section in the ffmpeg-utils manual.*

### Request Example
```json
{
  "filter": "life",
  "options": {
    "f": "pattern",
    "s": "300x300"
  }
}
```

### Response
#### Success Response (N/A)
This filter generates video frames, not a direct API response.

#### Response Example
N/A

### Examples
* Read a grid from pattern, and center it on a grid of size 300x300 pixels:
```
life=f=pattern:s=300x300
```

* Generate a random grid of size 200x200, with a fill ratio of 2/3:
```
life=ratio=2/3:s=200x200
```

* Specify a custom rule for evolving a randomly generated grid:
```
life=rule=S14/B34
```

* Full example with slow death effect (mold) using `ffplay`:
```
ffplay -f lavfi life=s=300x200:mold=10:r=60:ratio=0.1:death_color=#C83232:life_color=#00ff00,scale=1200:800:flags=16
```
```

### OpenCL Program for Color Ramp Generation

```c
__kernel void ramp(__write_only image2d_t dst,
                   unsigned int index)
{
    int2 loc = (int2)(get_global_id(0), get_global_id(1));

    float4 val;
    val.xy = val.zw = convert_float2(loc) / convert_float2(get_image_dim(dst));

    write_imagef(dst, loc, val);
}

```

### CUDA Video Filters Overview

Source: https://ffmpeg.org/documentation.html/ffmpeg-all

Overview of CUDA video filters, including initialization and configuration requirements.

```APIDOC
## CUDA Video Filters

To enable CUDA and/or NPP filters, refer to the configuration guidelines for CUDA and CUDA NPP filters.
Running CUDA filters requires initializing a hardware device and passing it to all filters in a filter graph.

### Initialize Hardware Device

`-init_hw_device cuda[=name][:device[,key=value...]]`

Initializes a new hardware device of type `cuda` named `name`, using the given device parameters.

### Filter Hardware Device

`-filter_hw_device name`

Passes the hardware device named `name` to all filters in any filter graph.

For more detailed information see https://www.ffmpeg.org/ffmpeg.html#Advanced-Video-options

**Example:** Initializing the second CUDA device on the system and running `scale_cuda` and `bilateral_cuda` filters.
```
./ffmpeg -hwaccel cuda -hwaccel_output_format cuda -i input.mp4 -init_hw_device cuda:1 -filter_complex \
"[0:v]scale_cuda=format=yuv444p[scaled_video];[scaled_video]bilateral_cuda=window_size=9:sigmaS=3.0:sigmaR=50.0" \
-an -sn -c:v h264_nvenc -cq 20 out.mp4
```

CUDA filters operate exclusively on GPU memory. Frame data may need to be uploaded (`hwupload`) to hardware surfaces associated with the CUDA device before processing, and downloaded (`hwdownload`) back to normal memory afterward if required.

*   **`hwupload`**: Necessary if input frames are in CPU memory (e.g., software-decoded frames or frames processed by CPU-based filters).
*   **`hwdownload`**: Required if the output of CUDA filters needs further processing by software-based filters or saving in a format not supported by GPU-based encoders.

Note that `hwupload` uploads data with the same layout as the software frame. A `format` filter might be needed before `hwupload`. Similarly, `hwdownload` might not support all output formats, so a `format` filter could be needed after `hwdownload`.
```
